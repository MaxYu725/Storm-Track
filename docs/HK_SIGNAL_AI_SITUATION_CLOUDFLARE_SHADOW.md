# HK Signal AI Situation Analysis Shadow — Cloudflare Workers AI

Status: **MANUAL INFERENCE PROVIDER / SHADOW ONLY**

This provider attaches Cloudflare Workers AI to the immutable AI Situation Analysis Shadow packet corpus. It does not change frozen V1, V2 Shadow, evaluator, closeout, HKO truth attribution, or any deterministic coefficient/threshold.

## Provider choice

Current pilot model: `@cf/openai/gpt-oss-120b`.

The adapter uses the Cloudflare Workers AI OpenAI-compatible Chat Completions endpoint:

```text
POST https://api.cloudflare.com/client/v4/accounts/{account_id}/ai/v1/chat/completions
```

It requests JSON Schema output and then applies the repository's own strict local validator. Provider schema-following is not trusted as the only correctness layer.

## Closed-book evidence contract

The model receives:

1. `hk-situation-analysis-prompt/v0.5` system instructions;
2. one saved `hk-situation-analysis-shadow-input/v0.1` evidence packet;
3. that packet's deterministic `hk-situation-analysis-evidence-catalog/v1`.

The packet may contain HKO operational context only when that context was already public at or before the prospective observation time and matches the reconciled storm identity. Future HKO truth, evaluator results, closeout outcomes and later observations remain excluded.

The model does **not** receive web search, tool calls, external meteorological data, hidden source-ID context or storm-specific prompt branches. Storm name, case ID, date, agency IDs and station names are provenance only.

## Evidence references

Free-form JSONPath references are no longer generated by the model. Each packet contains stable, storm-agnostic evidence IDs such as:

```text
E_V1_T3
E_REAPPROACH
E_TC_WIND_FIELD
E_HKO_SIGNAL_STATEMENT
E_LOCAL_WIND_SUMMARY
```

The request schema dynamically enumerates only IDs actually present in that packet. Repository-local validation independently rejects missing or invented IDs.

## Output contract

The response conforms to `hk-situation-analysis-shadow-output/v0.3` and includes:

- current operational lifecycle phase and confidence;
- prospective future phases;
- current threat interpretation;
- one signal-targeted next decision window;
- T1/T3/T8 interpretations;
- supporting/contradicting evidence;
- model semantic concerns;
- explicit uncertainties.

Generic cross-field validation includes:

- `expected=false` + `unlikely` + no contemporaneous HKO context implies operational phase `remote`;
- without contemporaneous HKO context, maintenance/cancellation/escalation cannot be inferred;
- maintenance/cancellation apply only to the currently active HKO signal tier;
- escalation applies only to a tier above the active HKO tier;
- `not-applicable` pairs with `nextQuestion=none`;
- supports-maintenance/cancellation/escalation must match the corresponding question;
- a T1/T3/T8 decision window must match that signal's own next question;
- cyclone-centre/representative wind cannot be treated as Hong Kong local wind or directly compared with local signal thresholds.

No replacement risk/probability is generated.

## One-shot semantic repair

Cloudflare inference is allowed **at most one** deterministic repair attempt after a first response is valid JSON but fails repository-local structured-output validation.

The repair request receives only:

1. the **exact same immutable evidence packet**;
2. the model's previous invalid structured candidate;
3. the repository validator's error messages.

Validation errors are diagnostics, not meteorological evidence. The repair request cannot add truth data, later observations, web/tool data, external weather information or case-specific rules.

The repaired candidate is passed through the exact same local validator. If it still fails, the inference fails closed and nothing is persisted.

Inference records expose:

```text
provider.attemptCount
provider.repairAttempted
provider.attempts[]
repair.initialValidationErrors
prompt.initialRequestFingerprint
prompt.repairRequestFingerprint
```

The final `prompt.requestFingerprint` identifies the request that produced the accepted output.

## Runtime settings

Current defaults:

```text
model       @cf/openai/gpt-oss-120b
max_tokens  6000
temperature 0.2
seed        725
stream      false
```

`reasoningControl` is recorded as `provider-default` because this Chat Completions contract does not depend on a provider-specific reasoning-effort switch.

## Credentials

The GitHub Actions workflow accepts:

```text
CLOUDFLARE_ACCOUNT_ID   preferred
CLOUDFLARE_API_TOKEN    preferred
CF_ACCOUNT_ID           fallback
CF_API_TOKEN            fallback
```

The API token must include Workers AI permission. Secrets are never written to repository files or inference records; the stored endpoint is normalized with `{account_id}`.

## Workflow and persistence

`.github/workflows/hk-situation-analysis-cloudflare-shadow.yml` remains `workflow_dispatch` only. `case_id` must be an exact stable case ID in the latest immutable packet batch.

Successful outputs are written to:

```text
data/hk-situation-analysis-shadow-inferences
```

Immutable provider history:

```text
inferences/<case-id>/cloudflare-workers-ai/YYYY/MM/DD/...
```

Provider-specific convenience pointers:

```text
cases/<case-id>/providers/cloudflare-workers-ai/latest.json
providers/cloudflare-workers-ai/latest.json
```

## Controlled pilot principle

Do not judge the provider using a single storm. Controlled comparisons use the same prompt, schema, model settings and no-future-truth contract across stress and ordinary-control cases. No case may receive a special rule merely because it exposed a previous failure.

## Promotion gate

Cloudflare Workers AI remains shadow-only until independent prospective evidence shows that it improves situation interpretation without degrading ordinary-path cases. Promotion requires lifecycle-phase correctness, evidence-reference discipline, operational-action applicability, timing interpretation, contradiction detection, uncertainty calibration and ordinary-case regression checks.
